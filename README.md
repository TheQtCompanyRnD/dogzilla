## Dogzilla daemon

The code in the `dogzillad/src` directory comprises an attempt to replace `
DOGZILLA/app_dogzilla/app_dogzilla.py` on the 
[Dogzilla S2](https://category.yahboom.net/products/dogzilla-s1?variant=46390953640252)
with a Qt-based daemon, using ROS as one means of remote control / monitoring,
in addition to the game controller.

It can be built and run in the usual way, provided that the qml/QtRos2 modules
are installed: cmake, make, dogzillad.  It loads `main.qml` at startup, and much
of the behavior can be defined there.

## Building the custom message type, testing telemetry

```
$ cd /path/to/dogzilla
$ colcon build --packages-select dogzilla_interfaces --symlink-install
$ source install/setup.bash
$ ros2 run rqt_plot rqt_plot /dogzilla/telemetry/system/cpu_percent /dogzilla/telemetry/system/fan_level /dogzilla/telemetry/temperature/temperature
$ ros2 topic echo /dogzilla/telemetry/system
fan_level: 1
cpu_percent: 4.0

^C
$ ros2 topic echo /dogzilla/telemetry/temperature

---
```

## Digital Twin (client)

The `digitwin` directory contains a 3D scene generated by the URDF2Quick3D tool.
It will be turned into a means of monitoring and controlling the robot via ROS
topics.

First, do the `colcon build` step above, because the digital twin depends on
the custom telemetry message type.

Then, this can be built and tested in the usual Qt way:

```
$ cd digitwin
$ qt-cmake .
$ make
$ qml -I . Main.qml
```
If both are on the same network (wifi or ethernet), they should talk to each
other.
